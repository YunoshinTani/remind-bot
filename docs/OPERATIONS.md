# 日誌リマインダーBot 運用手順

[READMEへ戻る](../README.md) · [ディレクトリ構成](STRUCTURE.md)

本番の設定・名簿・トークン・DBは運用サーバーで管理します。PCはコードの編集・テスト・配布用です。以下の接続先・氏名・日付は説明用の例です。実際の運用先やDiscord投稿の詳細は、開発者へDiscordのDMでお問い合わせください。

## 1. 通知と回収の動作

| 項目 | 動作 |
| --- | --- |
| 朝 | 設定時刻に担当者へメンションし、回収ボタンを表示 |
| 昼 | 未回収の場合だけ、設定時刻にeveryone通知を1回 |
| 回収期限 | 本文に表示する期限。期限到達による追加通知はなし |
| 回収記録 | 最初にボタンを押した人と時刻を保存 |
| 提出通知 | 設定で有効にした場合、授業終了時に担当者へ通知 |
| 当番 | 登校日ごとに次の組へ進む。最終組の次は先頭へ戻る |
| 対象外の生徒 | 名簿の `active=false` で除外。組のもう一人はそのまま担当 |

回収したら必ず「回収しました」を押してください。記録がない場合は未回収と判定します。日誌チャンネルを見られるメンバーは代理でも押せます。回収期限後も当日中は操作でき、翌日の当番は回収状態に関係なく登校日の巡回で決まります。

回収済みの投稿には記録時刻と記録者を表示します。代理で押した場合も、最初に押した人を記録します。表示の更新で再メンションは送りません。

## 2. 運用サーバーでの起動と停止

PCから、実際の接続先に置き換えてログインします。`server.example.invalid` は接続できない例示用ホストです。

```powershell
ssh botuser@server.example.invalid
```

ログイン後、サーバーで実行します。

```sh
cd ~/remind-bot-centos7
./bot.sh status
tail -n 30 data/bot.log
```

`status` はプロセスの確認です。Discord接続は、今回の起動後のログに「Discord に接続しました」があることを確認します。

```sh
./bot.sh stop
./bot.sh start
./bot.sh status
```

`start` はバックグラウンド起動です。通常はSSHを閉じても動き続け、PCは停止できます。初回はログアウト後に再接続し、継続稼働を確認してください。サーバー再起動後の自動起動・異常終了時の自動復帰は同梱していません。

通知の判定間隔と猶予時間は設定で指定します。猶予を過ぎた古い通知は自動送信しません。必要なら実際の投稿を確認し、管理者が [`/remind`](#12-管理者が通知を手動送信する) を使います。

## 3. 日々の確認

| コマンド | 表示・操作 |
| --- | --- |
| `/today` | 今日の当番と回収状態を本人だけに表示 |
| `/next` | 自分の次の担当日を、今日を含め90日先まで検索 |
| `/schedule` | 今日の時間割を取得 |
| `/schedule date:2026-10-19` | 指定日の時間割を取得。`YYYY/MM/DD` も使用可能 |

日誌チャンネルで実行してください。コマンドの照会結果は本人だけに表示され、他の担当者へメンションしません。朝・昼の定時通知はチャンネル全体に表示します。

`/next` は休日・対象外の生徒・登校日ごとの巡回を考慮します。時間割の変更で予定が前後することがあります。未来の当番・回収・通知記録を確定しません。

`/schedule` はMyiD連携時に利用できます。毎回取得し、時限・時刻・科目・教室・担当教員を表示します。休講は休講として表示し、未登録項目は省略します。取得失敗は休校と判断しません。授業詳細や照会結果は本番DBへ保存しません。

## 4. 確認・テスト用コマンド

本番の確認は運用サーバーの設置先で行います。

| コマンド | 内容 |
| --- | --- |
| `./bot.sh doctor` | 同梱環境・設定・外部接続を確認。投稿・本番DB変更なし |
| `./bot.sh check` | 設定・登校日・当番を確認。投稿なし |
| `./bot.sh preview --date 2026-10-15` | 指定日の通知文を表示。投稿なし |
| `./bot.sh members` | 名簿とDiscordの照合。投稿なし |
| `./bot.sh members --save` | 照合できたID・表示名をCSVへ保存 |
| `./bot.sh test` | メンションなしのテスト投稿と回収ボタンを確認 |
| `./bot.sh unit-tests` | 自動テスト。Discordへの接続・投稿なし |

実際の投稿を試す場合は、通常のBotを停止してから実行します。

```sh
./bot.sh stop
./bot.sh test
./bot.sh start
./bot.sh status
```

テスト投稿の「回収テスト」を5分以内に押します。本番の当番・回収記録は変更しません。PCの表示確認は、架空データの `examples/config.demo.toml` を使ってください。

## 5. 名簿・Discord名の変更

運用サーバーの `roster.csv` を編集します。PC側へ本番名簿を同期しません。

| 列 | 内容 |
| --- | --- |
| `number` | 出席番号。1番から最終番号まで、対象外の人も行を残す |
| `name` | 氏名。氏名の間に空白を入れない |
| `discord_id` | DiscordユーザーID。名前より優先 |
| `active` | 担当する人は `true`、対象外の人は `false` |
| `discord_name` | 例外的な照合名、または同期時のDiscord表示名 |

名前からの照合は `01-青空太郎` のような「番号-氏名」と完全一致で行います。番号だけの推測や部分一致は使いません。同名候補が複数ありID未登録の場合は未解決になります。IDを登録済みならそのアカウントを優先します。

```sh
./bot.sh stop
./bot.sh members --save
./bot.sh start
```

照合できたID・表示名だけを保存し、変更前のCSVを `backups/` に残します。氏名・在籍状態・未解決の行は保持します。一部未解決の場合も「名簿を更新しました」と出ていれば、照合できた分の保存は完了しています。変更がなければ新しいバックアップは作りません。

正式氏名や `active` は手動で修正し、UTF-8で保存してください。大きなDiscord IDは表計算ソフトで数値変換させないよう、文字列で扱います。

担当者を照合できない場合も通知は送ります。照合できる人はメンションし、できない人は番号・氏名で表示します。サーバー未参加の本人には個別通知を届けられません。対象外の人の行を削除して番号を詰める必要はありません。

## 6. 通知時刻・通知先の変更

運用サーバーの `config.toml` をバックアップし、既存の項目を編集します。以下は仮の値です。

```toml
[notifications]
timezone = "Asia/Tokyo"
morning_time = "08:10"
lunch_time = "12:10"
lunch_end_time = "12:50"
pickup_location = "担当教員の部屋の前"
submission_location = "担当教員の部屋の前"
dismissal_enabled = false
dismissal_time = "16:20"
grace_minutes = 5
poll_seconds = 20
```

実際の回収・提出場所は、この設定にだけ記載します。場所は1〜200文字の1行で指定してください。省略すると「担当教員の部屋の前」です。実在の教員名・場所を公開ソースへ書き込む必要はありません。

朝・昼は設定した固定時刻です。MyiD上の始業時刻に合わせて自動変更しません。回収期限は本文の表示用で、追加通知時刻ではありません。提出通知を有効にすると、有効な授業の最終終了時刻を使います。終了時刻がない日程では設定の既定値を使います。

通知先は `[discord].channel_id` を変更します。`guild_id=0` の場合は通知先からサーバーIDを取得します。保存後に `./bot.sh check` で検証し、Botを再起動してください。通常のコード更新は設定を転送しません。

## 7. 休校・行事・時間割変更への対応

MyiDに休講でない授業がある日を登校日とします。授業なし・全件休講なら通知も当番の交代も行いません。取得失敗や不正な応答では判定を保留します。当日の日程は既定で最長5分キャッシュし、過去の日程は保存結果を使います。

授業のない行事などは、サーバーの `calendar-overrides.json` で上書きできます。

```json
{
  "days": [
    {"date": "2026-10-20", "is_school_day": false},
    {"date": "2026-10-21", "is_school_day": true, "lunch_time": "12:10"}
  ]
}
```

設定の既存の `[calendar]` に `overrides_file = "calendar-overrides.json"` を指定し、対象日の `preview` で確認します。初めて有効にしたら再起動してください。記載のない日は通常のAPI判定です。指定済みJSONの内容は次の判定で読み直します。

保存済みの担当は日程変更だけで自動的に入れ替わりません。過去日程の変更は巡回に影響するため、先にバックアップし、確定済み担当との整合を確認してください。

## 8. 当番の開始位置を変更する場合

`[rotation]` の `start_date` と `first_pair` を変更します。組番号は在籍設定で除外する前の番号です。1は1・2番、2は3・4番を表します。

設定だけでは既にDBへ確定した担当は変わりません。当日を訂正する場合は、管理者が `/remind` の確認画面で新しい担当を確認して送信します。未回収かつ朝通知の訂正に対応します。コマンドを実行しただけでは送信しません。

運用全体を新しい起点から始め直す場合は、停止・バックアップ後、開始日と組番号を変更し、`[storage].database` を新しいファイル名にします。`check --date 対象日` で確認し、まだ通知していない開始日に合わせて再開してください。新しいDBには以前の回収・重複防止記録がありません。通常の訂正目的でDBを削除しないでください。

## 9. バックアップと復旧

保存するものは `config.toml`・`roster.csv`・`.env`・DBを含む `data/` と、使用中の日程ファイルです。DBを別の場所に指定した場合は、そのファイルも対象です。Botを停止してから最新のファイルを保存します。

```sh
./bot.sh stop
umask 077
backup_dir="backups/manual-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
cp -- config.toml roster.csv .env "$backup_dir/"
cp -a -- data "$backup_dir/"
if [ -f calendar-overrides.json ]; then
    cp -- calendar-overrides.json "$backup_dir/"
fi
./bot.sh start
```

復旧はBotを停止し、対応する設定・名簿・DBを戻して再開します。古いDBには、その後の通知や回収が記録されていない点を確認してください。バックアップには認証情報・個人情報が含まれるため、管理者だけがアクセスできる場所で保管します。公開用ZIPやReleaseには添付しません。

## 10. 困ったとき

| 症状 | 確認するもの |
| --- | --- |
| オフライン | `status` と今回の起動後の `data/bot.log` |
| 通知がない | 登校日・猶予時間・回収状態・送信済み記録・権限 |
| 個人メンションがない | `members` の照合結果とServer Members Intent |
| `Missing Access` / `Forbidden` | サーバー参加・チャンネル権限・Intent |
| `LoginFailure` | サーバーの `.env` にあるトークンの有効性 |
| 判定保留 | `check`・対象日の `preview` と時間割API |
| 送信結果が不明 | チャンネルの実際の投稿。重複を避けて自動再送を停止する仕様 |
| 回収ボタンが反応しない | Botの稼働・当日の通知か・テスト受付中か |
| `PyNaCl` / `davey` 警告 | 音声機能用。通知・回収ボタンには影響なし |

コマンドが見えない場合は接続ログ・コマンド登録権限を確認し、Discord画面を開き直してください。トークン・実名簿・非公開URLを公開Issueやログの引用へ含めないでください。

## 11. 別のPC・常時稼働サーバーへ移す場合

元のBotを停止し、最新の設定・名簿・トークン・日程・DBをバックアップして移行先へ引き継ぎます。移行先のOSに対応したPython 3.11以降と依存ライブラリを用意します。Windowsの `.venv` をLinuxへコピーしません。

`check`・`members`・必要なら `test` で確認し、移行先だけで本番を起動します。DBも移すことで回収・重複防止記録を引き継ぎます。CentOS 7向け同梱環境は [専用手順](CENTOS7.md)、新しいPCは [初期設定](START_HERE.md) を参照してください。

## 12. 管理者が通知を手動送信する

日誌チャンネルで `/remind` の `kind` から朝・昼を選びます。操作する人のサーバー管理者権限が必要です。Bot自体に管理者権限は必要ありません。

1. 本人だけに表示される確認画面で、日付・担当・本文を確認する。
2. 「送信する」または「担当を訂正して送信」を押す。中止は「キャンセル」。確認の有効期限は3分。
3. チャンネルへの投稿結果を確認する。

予定時刻や送信済み状態に関係なく、確認した通知を追加送信できます。ボタン連打は1回に制限し、同種の自動通知の重複も防ぎます。送信前に日程を再取得し、休校・回収済み・確認後の内容変更があれば送信を止めます。手動投稿の回収ボタンも通常の回収記録を共有します。
