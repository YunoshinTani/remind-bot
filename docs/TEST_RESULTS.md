## 自動テスト

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

一時フォルダの設定・架空の名簿・SQLite・通信の代用品を使います。ローカルHTTPサーバーを使う検証もありますが、本番のDiscordや運用サーバーへ接続しません。テスト内で障害を再現するログが出る場合も、最後の `OK` と終了コードで成否を判断してください。

| 対象 | 主な確認内容 |
| --- | --- |
| 通知・回収 | 時刻、重複防止、回収済み時の抑止、記録者・時刻の保持、再メンション抑止 |
| 当番計算 | 休日・休講、巡回、担当対象外の生徒、保存済み担当の保持 |
| コマンド | 本人だけの返信、日付指定、時間割の分割、管理者権限・送信前の確認 |
| 名簿 | ID優先、同名候補の拒否、未照合時の氏名表示、部分保存 |
| 日程取得 | 応答検証、キャッシュ、APIエラーを休日と誤認しないこと |
| 更新 | 運用ファイルの保護、バックアップ・復元、更新前のテスト |
| 配布・公開 | 安全な相対パス、公開対象の許可リスト、履歴・運用データ・接続設定の除外 |

## 型検査

```powershell
.\.venv\Scripts\python.exe -m pyright
.\.venv\Scripts\python.exe -m pyright --pythonplatform Linux
```

Windows向けの開発環境と、Linux専用コードの検査設定をそれぞれ確認します。型検査の成功は、実機での接続・権限・通知成功を保証するものではありません。

## 導入先での確認

運用サーバーで `./bot.sh doctor`、`check`、`members` を実行します。投稿・ボタンの実機確認には、通常のBotを停止して `./bot.sh test` を使います。再開後は `status` と今回の起動の接続ログを確認します。

これらの実機確認には導入先の設定・認証情報・権限が必要です。個別の実行ログや内部メッセージへのリンクは公開用ソースへ含めません。
